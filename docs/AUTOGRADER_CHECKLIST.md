## 1. Global Autograder Traps & Envelope Rules

| Rule ID | Rule / Trap Description | Autograder Requirement | Implementation Safeguard |
| :--- | :--- | :--- | :--- |
| **G-01** | **Error Envelope (Non-2xx)** | Every non-2xx response MUST use envelope `{"error": {"code": "...", "message": "...", "details": {}}}`. Never return FastAPI's default `{"detail": ...}`. | Custom global exception handlers for `HTTPException`, `RequestValidationError`, and `500`. |
| **G-02** | **Validation Error Code & Status** | FastAPI returns 422 by default; **spec strictly demands HTTP 400 `VALIDATION_ERROR`** with `details.fields` list. Malformed JSON $\to$ 400. | Override `RequestValidationError` handler to return 400 and map bad field names. |
| **G-03** | **Strict Pydantic Types** | `"5"` must NOT be accepted as integer; `true` must NOT be accepted as `1`. Unknown fields ignored (`extra="ignore"`), never rejected. | Use Pydantic `ConfigDict(strict=True, extra="ignore")`. |
| **G-04** | **Check Order Precedence** | Evaluation order: 1. `400` (schema/validation) $\to$ 2. `404` (referenced id not found) $\to$ 3. `409`/`402` (business rules). | Enforce deterministic guard clauses in router dependencies and controllers. |
| **G-05** | **Identifier Regex** | `^[A-Za-z0-9_.:-]{1,64}$` case-sensitive. `sport_id`: `^[a-z0-9_-]{2,40}$`. Pipes `\|` are invalid $\to$ 400. | Pydantic regex validator on string identifier fields. |
| **G-06** | **Strict Timestamps & Money** | Timestamps: `YYYY-MM-DDTHH:MM:SSZ` (no microsec, no `+00:00`). Dates: `YYYY-MM-DD`. Money: Integer in paisa (`minor units`), currency `"PKR"`. | Custom datetime serializer `strftime("%Y-%m-%dT%H:%M:%SZ")`. |
| **G-07** | **Idempotency** | Same client ID with identical canonical body $\to$ **200 with stored response**. Same ID with different body $\to$ `409 DUPLICATE_*`. | Compare canonical JSON hash `json.dumps(obj, sort_keys=True, separators=(',', ':'))`. |
| **G-08** | **Payload Limit** | Request body $> 1$ MB $\to$ **413 `PAYLOAD_TOO_LARGE`**. | Raw stream length check middleware before JSON parsing. |
| **G-09** | **Zero Hardcoded Sports** | Never branch on a sport or event name (e.g. "football", "goal") $\to$ costs -8 pts penalty. Branch only on `scoring_model`. | Seed sports loaded from external JSON data file. |

## 2. Master Endpoint Compliance Matrix

### R1: Health Probe & Platform Reset (§5.4, §5.5)
* **`GET /health`**
  - **Auth:** None
  - **Status Code:** `200 OK`
  - **Response Schema:** `{"status": "ok"}`
  - **Rule:** Returns 200 ONLY when DB is reachable and baseline data is seeded.
* **`POST /audit/v1/reset`**
  - **Auth:** None
  - **Payload (Optional):** `{"seed": 42, "stock": {"var-jersey-001-M": 1, "var-jersey-001-L": 5}}`
  - **Status Code:** `200 OK`
  - **Response Schema:** `{"status": "reset_complete", "seed": 42, "sports": [...], "tenants": ["tenant-alpha", "tenant-beta"], "stock": {...}}`
  - **Rule:** Wipes all state (`TRUNCATE ... CASCADE`), clears in-memory caches and rate limits, reseeds exact IDs, leaves identical state on repeated calls.

### R2: Dynamic Sports Engine & Schema Validation (§5.6)
* **`POST /audit/v1/sports`**
  - **Auth:** None
  - **Payload:** `{ "sport_id": "padel", "name": "Padel", "scoring_model": "round", "config": { "sets_to_win": 2, "games_per_set": 6 } }`
  - **Success:** `201 Created` $\to$ echoes sport configuration.
  - **Validation Errors:** `400 VALIDATION_ERROR` for malformed IDs or unsupported scoring models; `409 SPORT_EXISTS` if ID taken.

---

### R3: Pure Fixture Scheduling Engine (§5.7)
* **`POST /audit/v1/fixtures`**
  - **Auth:** None
  - **Supported Types:**
    1. **Round-robin (`type: "round_robin"`):** Circle method; handles odd $n$ with byes; leg 2 mirrored with global round numbering; match ID `RR-L{leg}-R{round}-M{index}`; withdrawal policies (`void_all` vs `forfeit_remaining`).
    2. **Swiss (`type: "swiss"`):** R1 seed $i$ vs $i+\lfloor n/2 \rfloor$; rounds $\ge 2$ memoized backtracking DFS minimizing sum of score diffs; byes to lowest-scoring eligible team; Buchholz tie-breaking; returns `409 NO_VALID_PAIRING` if no rematch-free pairing exists.
    3. **Single Elimination (`type: "single_elimination"`):** Next power-of-2 bracket; recursive seed ordering; bye winners advance automatically; optional third-place match (`TP`).
    4. **Double Elimination (`type: "double_elimination"`):** Winner and Loser brackets; losers drop to LR; Grand Final `GF2.conditional` requires true only when losers bracket champion wins GF1.
  - **Success:** `200 OK` with full fixture tree. Pure computation (stores nothing).

---

### R4: Event-Sourced Scoring Engine (§5.8, §5.9)
* **`POST /audit/v1/events`**
  - **Auth:** None
  - **Types:** `match_init`, `match_start`, `score`, `discipline`, `tiebreak_winner`, `match_end`, `compensate`.
  - **Success:** `201 Created` with signed event record (`signature` = HMAC-SHA256 of `event_id + "|" + canonical(payload)` using `DAY1_SALT`).
  - **Rules & Status Codes:**
    - `match_init` on existing match $\to$ `409 MATCH_EXISTS`.
    - Event on missing match $\to$ `404 MATCH_NOT_FOUND`.
    - Event when match not in progress $\to$ `409 MATCH_NOT_IN_PROGRESS`.
    - Target event missing on compensate $\to$ `404 EVENT_NOT_FOUND`.
    - Target already compensated or wrong match $\to$ `409 INVALID_COMPENSATION`.
    - Level score on `match_end` with `draw_allowed: false` $\to$ `409 TIE_NOT_ALLOWED`.
    - Innings sport limit reached $\to$ `409 INNINGS_COMPLETE`.
* **`GET /audit/v1/score/{match_id}`**
  - **Status Code:** `200 OK`
  - **Rule:** Recomputed from event log on read. Compensated events are neutralized.

---

### R5: Tournament Standings Engine (§5.10)
* **`GET /audit/v1/standings/{league_id}`**
  - **Auth:** None
  - **Success:** `200 OK`
  - **Rules:**
    - Points: W=3, D=1, L=0 (or sport config).
    - Recursive `resolve(group)`: 3-way tied groups compute H2H points and goal diffs **exclusively among tied members**.
    - Innings diff = Net Run Rate (NRR) to 3 decimals: $(\text{runs}/\text{overs faced}) - (\text{conceded}/\text{overs bowled})$.
    - Drawing of lots: Deterministic ascending SHA-256 `sha256(f"{seed}|{league_id}|{team_id}")`.
    - Clinched / Eliminated math based on maximum remaining points.

### R6: Roster Management & Transfer Windows (§5.11)
* **`POST /audit/v1/roster/transfer`**
  - **Auth:** None
  - **8-Step Strict Failure Check Order (First Failure Wins):**
    1. `400 VALIDATION_ERROR` (Bad dates: `loan_end_date <= effective_date`; missing `to_squad_id`).
    2. `404 *_NOT_FOUND` (league, player, or squad missing).
    3. `409 CROSS_TENANT_TRANSFER` (inter-tenant transfers prohibited).
    4. `409 NOT_IN_SQUAD` (player not in source squad).
    5. `409 TRANSFER_WINDOW_CLOSED` (outside active window; release always allowed).
    6. `409 PLAYER_ON_LOAN` (player currently loaned).
    7. `409 SQUAD_FULL` (destination squad at maximum limit).
    8. `409 MIN_POSITION_VIOLATION` (source squad drops below required position count).
  - **In-Progress Match:** Accepted with `state: "deferred_until_match_end"` and `blocking_match_id`.
  - **Loan Auto-Return:** Querying `GET /audit/v1/roster/history?as_of=<date>` appends `loan_return` (`who: "system"`) exactly once.

### R7: Merchandise Store & Concurrency Burst (§5.12)
* **`POST /audit/v1/checkout`**
  - **Concurrency Stress Test:** 20 parallel threads on last 1 stock item.
  - **Success:** Exactly **one 201 Created**; exactly **nineteen 409 OUT_OF_STOCK**.
  - **Inventory Post-Burst:** `stock = 0`, `reserved = 0` (never negative).
  - **Payment Tokens:**
    - `tok_success`: Commits order, marks `paid`, generates signed PDF receipt.
    - `tok_declined`: `402 PAYMENT_DECLINED` $\to$ releases reserved stock.
    - `tok_capture_fail`: `402 PAYMENT_CAPTURE_FAILED` $\to$ releases reserved stock.
  - **Discounts:** Only `WELCOME10` valid (10% floor discount); unknown code $\to$ `400 INVALID_DISCOUNT_CODE`.
  - **PDF Receipt:** Decodes to `%PDF`, includes `order_id` and formatted PKR (`PKR 4500.00`).
* **`GET /audit/v1/inventory/{variant_id}`**
  - **Status Code:** `200 OK` $\to$ `{"variant_id": "...", "stock": 0, "reserved": 0}`.

### R8: 5-Tier RBAC & 7 Probe Routes (§5.13)
* **`POST /audit/v1/rbac-matrix`** $\to$ Returns JWT tokens for 5 seed accounts.
* **7 Probe Routes (No payload validation, authorization only):**
  - `P1`: `POST /audit/v1/rbac/tenants` $\to$ Super Admin only (200), others (403).
  - `P2`: `POST /audit/v1/rbac/leagues/{league_id}/fixtures` $\to$ Super Admin & League Organizer on own league (200), others (403).
  - `P3`: `POST /audit/v1/rbac/clubs/{club_id}/roster` $\to$ Super Admin & Club Manager on own club (200), others (403).
  - `P4`: `POST /audit/v1/rbac/clubs/{club_id}/products` $\to$ Super Admin & Club Manager on own club (200), others (403).
  - `P5`: `PATCH /audit/v1/rbac/players/{player_id}` $\to$ Super Admin, Manager (own player), Player (self) (200), others (403).
  - `P6`: `GET /audit/v1/rbac/clubs/{club_id}` $\to$ All roles allowed within `tenant-alpha` (200); Foreign club strictly **403 FORBIDDEN**.
  - `P7`: `GET /audit/v1/rbac/platform/config` $\to$ Super Admin only (200).
* **Security Checks:** Missing token $\to$ 401; `alg: none` $\to$ 401; Tampered token $\to$ 401.
* **Rate Limit:** `GET /api/v1/ping` $\to$ 100 req / rolling 10s per IP; 101st+ returns `429 RATE_LIMITED` with `Retry-After`.

### R9: Offline Mobile Sync Queue (§5.14, §8.4)
* **`POST /audit/v1/offline-sync`**
  - **Payload:** `{"device_id": "dev-1", "actions": [...]}` (1 to 100 items).
  - **Processing Order:** Server sorts by `queued_at ASC`, processes sequentially.
  - **Response Order:** Results returned in original request order with `processed_order`.
  - **Conflict Resolutions:**
    - `applied` / `appended` (base_version == current_version)
    - `applied` / `rebased_append` (base_version < current_version)
    - `duplicate` / `skipped_duplicate` (seen action_id or identical event_id)
    - `rejected` / `server_wins` (`INVALID_BASE_VERSION`, `SQUAD_FULL`, etc.)
  - **Status Code:** Always `200 OK` (errors captured per action in `results` array).
